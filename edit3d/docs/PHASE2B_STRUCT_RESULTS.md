날개끝 토큰(축0 > 75% 분위, **1995개**)을 SLat 에서 삭제, 절단 경계밴드(3복셀, 1019토큰)만 재생성.

| 판별 | 결과 |
|---|---|
| 제거 bbox 디코드 점유 | **1994 → 0** (구조가 실제로 사라짐) |
| 비편집 영역(축0 < thr-4) 점유 IoU | **1.000** |
| 정성(정면뷰) | 한쪽 날개 전체가 깨끗하게 제거, 이음매 없음 |

## A — 추가 (돌출 슬래브) ✅

⚠️ 함정 발견: **정규화가 최장축(날개폭)을 큐브에 꽉 채우므로 그 방향(축0)으론 추가 공간이 없다**
(max=63=그리드 끝). → 그리드 여유가 가장 큰 축·방향을 자동 선택(축2 max 쪽)해 접경 단면 중앙 60%
크기의 bbox(깊이 4~6복셀)를 `fill_bbox_coords` 로 채움. **extra=2200 복셀**, 접경 블렌드 259토큰.

| 판별 | 결과 |
|---|---|
| 추가 bbox 디코드 점유 | **0 → 2200 (100% 채움)** — flexible dual grid 디코더가 비워두지 않고 stage-2 가 전부 형상화 |
| 비편집 영역 IoU (추가 bbox+2 팽창 제외) | **1.000** |
| 정성(톱뷰) | 상단에 초록 슬래브 돌출 — 추가 구조가 명확히 생성됨 |

> 러너의 1차 `unedited_iou=0.802` 는 **검증 영역 정의 실수**(검증 영역이 추가 bbox 를 관통해 추가분이
> '변화'로 집계됨). 추가 bbox 를 제외하고 재계산하면 1.000. 판별 로직 주의점으로 기록.

## 결론

**§4a 의 "coords 집합 직접 조작" 근사가 성립한다** — stage-1 encoder 없이도:
- 제거: 토큰 삭제 + 경계밴드 재생성으로 깨끗한 절제
- 추가: bbox 채움 + 블렌드로 새 구조 생성(디코더가 채운 복셀을 실제 형상화함을 실측 확인)
- 두 경우 모두 비편집 영역 완전 불변(IoU 1.000)

Phase 2 게이트(마스킹 역학) + Phase 2b(구조 변화) 로 **C(Region Editing)의 기술 스택 전체가 검증됨.**

## 함정/노트 (후속 구현 시)

1. **최장축 방향으론 추가 불가** — 정규화 규약상 그리드에 여유가 없다. 편집 UI/API 는 추가 방향의
   그리드 여유를 사전 검증해야 한다.
2. 추가 bbox 는 **기존 구조와 접해야** 자연스럽다(접경 단면 중앙 60% 사용). 허공에 띄우면 미검증.
3. 슬래브가 100% 채워졌다 = stage-2 는 "열린 복셀은 채우는" 경향. **정밀한 형상 통제(예: 뿔 모양)는
   조건 이미지가 담당**해야 한다 — 다음 단계(의미 편집)의 근거.
