# 에셋 작업실 — USD 결과 검토·재생성 UI

내부망 주소: **http://10.254.62.200:8766**. 기존 이미지 비교 페이지(8765), 부분편집 앱과 별도 서비스다. 외부 CDN·웹폰트 없이 로컬 Three.js r160으로 실제 GLB를 표시한다.

## 제공하는 흐름

- USD 생성 결과의 최신 GLB·참조 이미지 가져오기. 기본 등록 폴더를 30초마다 확인하며 수동 가져오기 버튼도 제공한다. 최초 시작 시에도 가져온다.
- 원본을 작업실 저장소로 복사하고 이후 결과를 새 버전으로 보존한다. 이미지 업로드는 PNG/JPG/WebP, 3D 업로드는 텍스처가 포함된 GLB를 받는다.
- 중앙 Text to Image / Image to 3D Object 탭. T2I는 같은 입력·설정과 서로 다른 seed의 후보 4장을 2×2로 표시한다. 묶음별 이력에서 선택하고 I23D로 넘긴다. 기존 단일 후보·업로드도 별도로 선택할 수 있다.
- 참조 이미지·배경 제거·실제 3D 입력 확인, 3D 회전/확대/앞·옆·뒤·아래·위, 재질/단색/와이어 표시, 두 GLB 버전 비교.
- 입력 원문·외형 정제 결과·템플릿 적용문·ERNIE 보강문 원본을 후보별 표시/복사. 중국어 보강문은 번역하지 않는다. 3D 재생성 버전도 원래 참조 이미지의 보강문·seed를 추적하며 새 3D seed와 구분한다. 업로드/미기록/생성 전에는 보강문이 없다는 상태를 표시한다.
- ERNIE PE ON과 메인 포즈 ON·3/4뷰 템플릿으로 이미지 후보 생성. Qwen INT8 Lightning 8-step 선택 가능. Qwen은 기존 실험과 같이 별도 자동 보강기를 적용하지 않는다.
- 이미지 생성 전에 메인의 `step2_filter_prompt.txt` 규칙으로 장면·동작을 정제한다. 기존 로컬 Ollama의 `gpt-oss:20b`를 CPU로 호출하며 메인 생성 코드는 변경하지 않는다. 같은 설명/객체/규칙/모델의 결과를 캐시해 후보마다 반복 정제하지 않는다. 정제 실패 시 장면 설명으로 조용히 폴백하지 않고 재시도 가능한 실패로 표시한다.
- 같은 이미지로 TRELLIS.2 재생성. 배경 제거 → 형상 → 내보내기를 별도 프로세스로 실행하여 각 단계 종료 시 VRAM 반환. 깊이 붕괴 감지 시 동일 이미지의 lift seed를 한 번 재시도하며 선택한 이미지를 몰래 바꾸지 않는다. 메인의 최종 T2I 재생성 재시도와 다른, 이미지 승인 흐름을 위한 차이다.
- 서버 저장 작업 대기열·현재 단계/경과 시간·중지·재시도. 브라우저와 작업 수명은 분리된다. 서버 정상 종료 시 실행 작업을 중단하고 재시도 가능하게 남긴다. 갑작스러운 종료로 남은 running 기록은 시작 시 interrupted로 표시한다.
- 단계별 NPZ/이미지 완료 파일과 metrics marker가 있으면 같은 작업 재시도에서 재사용한다. 다른 이미지/새 seed로 만드는 작업은 새 버전으로 실행한다.
- 즐겨찾기·이름 변경·메모·버전별 선택 완료. GLB 또는 GLB+이미지+기록 ZIP 다운로드. 선택 완료는 공인 품질 판정이 아닌 디자이너의 검토 표시다.
- 다운로드에만 높이(m)·중심/바닥 피벗·Y축 회전 적용. 원본 GLB와 텍스처 버퍼는 보존한다. 화면에서 보는 것은 원본 버전이며 다운로드 변환은 별도다. 크기를 지정하지 않으면 실제 크기를 추정하지 않는다.

## 시작·중지

현재 서버에서는 `trellis2` 환경을 사용한다. 모델 가중치는 이미 설치된 메인/실험 경로를 사용한다.

```bash
conda activate trellis2
python generation_ui/manage.py start --host 10.254.62.200 --port 8766 --gpu 1
python generation_ui/manage.py status
python generation_ui/manage.py stop
```

기본값은 물리 GPU 1이다. 다른 작업을 종료하거나 모델을 상주시켜 GPU를 선점하지 않는다. 메모리 여유가 22,000MiB 이상일 때 작업을 시작하며 작업실 자체 실행은 한 번에 하나로 직렬화한다. 별도 서비스가 이후 GPU를 점유하는 경우까지 예약·차단하는 전역 스케줄러는 아니다. 단일 GPU 순차 경로와 전체 VRAM은 실제 연결 시험 결과를 참고한다.

GPU 메모리 요구량·단계 지연은 개발 중 측정값이며 모든 입력의 시간/성공을 보장하지 않는다. 단계별 제한 시간은 30분, 최대 대기 작업은 30개다. 전체 생성 시간에 대한 가짜 진행률이나 1분 완료 약속을 표시하지 않는다.

수신 서버에서 경로가 다르면 `app.py --data ... --import-root ... --gpu ...`를 사용한다. 첫 번째 `--import-root`는 USD 결과 자동 탐색 루트이며 추가 루트는 참조 이미지/GLB 등록 허용 경로다. 기본값은 `movie_usd`, `t2o_pipeline/t2o_results`다. 자동 탐색은 `assets/` 아래 `*.glb.meta.json`이 있는 객체별 최신 GLB를 최대 100개 확인한다. 여러 과거 실행 전체를 일괄 복사하지 않는다. 필요하면 개별 등록 API를 사용한다.

## 이미지 후보·배경 문제 수정 (2026-09-09)

`POST /api/candidates`는 `count: 2|3|4`를 받으며 생략 시 기존 호환을 위해 4장이다. 화면 기본은 2장이고 마지막 선택을 브라우저에 기억한다. `seed_mode: random|manual`을 받으며 무작위 모드는 매 요청마다 새 시작 seed를 뽑는다. 직접 입력 모드는 `seed`가 필수다. 첫 seed에서 +0/+1/…을 사용하며 상한 2147470000에서만 범위 안으로 순환한다. 실제 목록은 응답의 `seeds`와 각 버전에 남긴다. 이미지와 3D seed 입력은 별개다.

각 후보의 job/version ID와 `batch_id`를 유지하면서 **한 묶음을 하나의 프로세스에서 모델 한 번 로딩으로 실행**한다. 외형 정제와 ERNIE 보강을 한 번 수행하고, 같은 보강문에서 diffusion seed만 달리한다. 보강 RNG는 시작 seed(`pe_seed`)를 사용한다. Qwen INT8은 기존대로 별도 PE 없이 정제·템플릿을 사용한다. 모델별 생성 파라미터·3/4뷰·리깅 포즈는 기존 경로와 같다. `/api/jobs`의 단일 이미지 호출은 호환성을 위해 그대로 유지한다. 후보 선택만으로 3D 생성이 시작되지는 않는다.

`GET /api/candidates/<batch_id>`는 공통 보강문과 실행 구간별 시간·진행도·시도 이력을 반환한다. 새 묶음의 중지/재시도는 `POST /api/candidates/<batch_id>/cancel|retry`이며 기존 job 중지/재시도 API에서도 새 묶음이면 전체 미완료 후보에 적용한다. 기존 독립 작업 기록은 계속 개별 제어한다. 완료 이미지와 마지막 marker를 함께 확인한 후보만 재사용한다. `shared.json`의 보강문은 실패/재시도에서도 재사용하며, 보강에 실패하면 원문으로 우회하지 않는다.

화면 시간은 대기, 실행 준비, 외형 정제, 모델 로딩, 보강, 텍스트 인코딩, 묶음별 이미지 생성(VAE 복호화·후처리 포함), 파일 저장으로 구분한다. GPU 단계 경계에서 동기화하고 단조 시계로 측정한다. 공통 시간을 후보마다 합산하지 않는다. 작업자가 실행 중일 때 `progress.json`을 원자적으로 저장하고 서버가 DB에 반영한다. 화면은 서버 시간 기준으로 매초 경과 시간을 표시한다. 완료·중지 후에는 고정값이며 이전 기록의 미측정 시간은 추정하지 않는다.

`candidate_profile.json`은 이 서버의 4090에서 실측한 생성 크기별 기록과 기본 처리 크기다. 프로필이 없거나 GPU가 다르면 모델을 한 번 올려 1장씩 처리한다. CUDA 메모리 부족에 한해서 묶음을 절반으로 줄이며, 일반 오류는 무조건 재시도하지 않는다. 완료 후보·보강문·seed·해상도·샘플링 단계는 보존한다. 병렬 수에 따라 부동소수점 계산이 달라질 수 있으므로 같은 seed의 픽셀 단위 동일성은 보장하지 않는다.

이전 UI는 USD의 `description_en`을 메인 외형 정제 없이 다시 T2I에 전달했다. 실제 자동차 입력에 페리 갑판·수린 탑승 정보가 남았고, ERNIE 보강문이 바다·갑판·하늘과 차체의 Su-rin 글자로 확장했다. `neutral background` 템플릿 누락이 아니며, 기존 비교 실험의 외형 중심 입력과 조건이 달랐다.

수정 후 경로는 **원문 → 메인 규칙의 외형 정제 → 기존 포즈/3/4뷰 템플릿 → ERNIE PE ON → 이미지**다. 단어만 추출하도록 바꾸지 않고 원래 규칙에 따라 색·형태·재질 등 외형을 유지한다. LLM 정제/보강이 항상 모든 외형을 보존하거나 배경을 완전히 배제한다고 보장하지 않으므로 중간 문장을 표시한다. T2I 원본의 중립 배경과 배경 제거 후 이미지도 구분한다.

정제 규칙은 메인 파일을 직접 읽는다. 실행은 UI의 로컬 Ollama `/api/chat`, gpt-oss:20b, CPU, temperature 0.2, seed 42, thinking low, 8192 context, 최대 2048 생성 토큰이다. 메인의 호출 온도/전송 방식까지 동일하다는 뜻은 아니다. `STUDIO_CAPTION_MODEL`, `STUDIO_CAPTION_URL`로 운영 설정을 바꿀 수 있다. 캐시는 작업실 데이터 폴더의 `caption_cache`이며 원문·객체·규칙·모델·구현 리비전으로 구분한다. 첫 설명 정제는 이번 자동차에서 약 53초였고 같은 설명의 후속 후보는 캐시를 사용했다. GPU에서 다른 모델을 내려달라는 요청은 하지 않으며 CPU 호출 종료 시 해당 CPU 모델을 반환한다.

참고 구현 규약: [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [thinking 설정](https://docs.ollama.com/capabilities/thinking).

## 묶음 생성 실측 (2026-09-09, RTX 4090 한 장)

같은 자동차 템플릿·시작 seed 197861·1024²·8단계로 비교했다. 아래 시간은 **공통 로딩·보강·인코딩과 별도 워밍업을 제외한 4장 생성·PNG 저장**이다. 기존의 후보마다 모델을 새로 올리는 시간과 혼동하지 않는다. 각 설정 1회 측정이며 다른 객체에서 같은 시간을 보장하지 않는다.

| 모델 | 1장씩 ×4 | 2장씩 ×2 | 3장+1장 | 4장 동시 | 4장 동시 최대 예약 VRAM |
|---|---:|---:|---:|---:|---:|
| ERNIE | 88.6초 | 63.3초 | 59.6초 | 46.9초 | 18.39GiB |
| Qwen INT8 | 50.4초 | 46.3초 | 46.1초 | 43.4초 | 22.91GiB |

두 모델 모두 N=2/3/4에 대해 N장을 한 번에 처리하도록 설정했다. 2·3장 정책은 측정한 묶음별 소요 시간으로 선택했다. 메모리 부족 시 작은 묶음으로 자동 전환한다. 측정 원문은 `docs/generation_ui_batch_benchmark_20260909.json`, 실제 LAN 생성 검증은 `docs/generation_ui_batch_smoke_20260909.json`에 있다.

재측정 도구는 `generation_ui/benchmark_candidates.py --gpu 1 --out <결과폴더>`다. 이 도구는 Studio GPU 잠금이 풀릴 때까지 기다리며, 사용자 작업을 종료하지 않는다. 결과를 확인한 후 `profile.json`을 `generation_ui/candidate_profile.json`에 반영한다.

## 통합 플랫폼 연결 계약

현재는 기존 메인 코드를 변경하지 않고 결과 폴더 감시로 연결했다. 생성이 끝난 플랫폼에서 아래 API로 등록하면 정확한 객체 ID와 검토 URL을 즉시 받을 수 있다. GLB 저장 완료 후 호출한다. 같은 경로·수정 시간·파일 크기의 재등록은 같은 버전을 반환한다. source_key는 USD 객체의 영속 식별자를 쓰면 된다.

```http
POST /api/import
Content-Type: application/json
X-Requested-With: GenerationStudio

{
  "glb_path": "/등록된/결과루트/assets/object_1/result.glb",
  "reference_path": "/등록된/결과루트/reference.png",
  "source_key": "project/scene_1/object_1",
  "object_path": "/World/scene_1/object_1",
  "project": "프로젝트 / 장면 1",
  "name": "주인공 갈매기"
}
```

응답: `asset_id`, `version_id`, `added`, `review_url`. 반환 URL을 통합 플랫폼의 '결과 검토' 링크로 사용할 수 있다. 필수는 `glb_path`이며 참조 이미지·설명·seed·객체 ID는 GLB sidecar에서 보완한다. 폴더 감시와 API를 함께 쓰는 경우 같은 객체에 동일한 source_key 정책을 사용한다. 폴더 감시의 기본 source_key는 GLB 부모 디렉터리 절대 경로다.

API가 수신하는 것은 등록된 서버 폴더의 파일이다. 다른 서버에서 만들어진 결과는 먼저 공유/등록 폴더로 전달해야 한다. 이 UI가 USD를 재파싱하거나 메인 플랫폼으로 변경 GLB를 자동 덮어쓰지는 않는다. 플랫폼으로 선택 버전을 재연결하는 계약은 review URL/버전 ID를 바탕으로 별도 확장할 수 있다.

- worker 로그는 서버에만 두며 임의 파일 경로로 제공하지 않는다. 사용자는 작업 보고서 JSON을 내려받아 작업번호와 설정을 전달할 수 있다.
- 기본 사내망 공동 작업용이며 로그인/사용자별 권한은 포함하지 않는다. 외부 공개용으로 구성하지 않았다. 변경 API에는 커스텀 헤더·동일 출처 확인을 적용하고, 파일 접근은 등록된 루트 및 버전 파일로 제한한다.
- 대상 DCC별 재질·리깅 호환성은 수신자의 실제 툴에서 확인해야 한다. FBX/USD 변환·자동 리토폴로지·부분편집·리깅 기능은 이 화면에 추가하지 않았다.
- 한글 설명도 외형 정제 단계를 거친다. 별도의 번역 전용 LLM은 추가하지 않았다. 원문과 정제 결과를 화면에서 확인할 수 있다.
- 선택적 WebMCP 탐색 도구는 기능 감지 후 등록한다. 지원 브라우저 컨텍스트를 이용한 WebMCP 실행 검증은 수행하지 않았다. 일반 UI 동작은 이 API에 의존하지 않는다.
