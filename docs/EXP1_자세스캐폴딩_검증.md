# EXP1 — 자세 스캐폴딩 검증 실험 계획

> 목적: 클래스별 자세 스캐폴딩 문구(무출처 자체 작성으로 판명, CONTEXT.md §4 2026-08-06 정정)가
> 실제로 자동 리깅 성공률을 올리는지 정량 검증한다.
> 겸용: 리깅 툴 선정(⭐ CONTEXT.md §7)의 근거 자료 + 결과에 예상 밖 구조가 보이면 논문화 후보.
> 작성: 2026-08-06

> **✅ 상태 (2026-08-11): 실험 완료 — 본 문서는 원계획 그대로 보존(수치 인용 금지).**
> 확정 결과·해석: `EXP1_rigging/EXP1_ANALYSIS.md` (§7 사람 채점 확정, §9 문구 개정안) /
> 실험 계보·run 매핑·재현 프로토콜·논문화 자산: `EXP1_rigging/MANIFEST.md`.
> 판정 요약: H1 부분 지지(quadruped·bird p=0.005 확정, biped·insect 무유의 → 정련·개정안),
> H2 기각(감쇠 없음 — S1 전결정, S2·S3 보존 100%), H3 재정의(병목은 리깅 "완료"가 아니라
> 부위별 본 품질). §7의 "클래스별 역전" 시나리오에 해당 → 논문화 재논의 조건 충족.

---

## 1. 가설

| ID | 가설 | 기각되면 |
| --- | --- | --- |
| H1 | 스캐폴딩 on이 off 대비 자동 리깅 성공률을 유의하게 올린다 | 스캐폴딩 무용 → 문구 제거 또는 재설계 |
| H2 | 자세 지시는 파이프라인을 통과하며 감쇠한다 (T2I 준수율 > I2O 후 유지율 > 리깅 성공률) | 감쇠 없음 → 병목은 다른 곳 |
| H3 | 리깅 실패의 상당 부분은 자세가 아닌 지오메트리 요인(얇은 구조 소실 등)에서 온다 | 자세가 지배 요인 → 스캐폴딩 문구 정련이 최우선 |

핵심은 H1의 성공/실패가 아니라 **깔때기의 어느 단계에서 새는지**다.
"on 95% vs off 60%"처럼 단조로우면 내부 자료로만 쓰고, 단계별 병목·클래스별 역전·
자세 무관 실패 지배 같은 구조가 보이면 논문화를 재논의한다(2026-08-06 대화 합의).

## 2. 실험 조건 (독립변수)

| 변수 | 수준 | 비고 |
| --- | --- | --- |
| 스캐폴딩 | on / off | off = 자세 문구만 제거, 격리·정면·전신 등 공통 문구는 유지 (자세 효과만 분리) |
| 클래스 | biped / quadruped / bird / insect | static_object 제외 (자세 강제 없음) |
| 객체 | 클래스당 5종 | 아래 목록. 프리비즈 대본에 나올 법한 것 위주 |
| 시드 | 3 | 시드 편차 실측(24s↔272s)이 크므로 최소 3 |

**객체 후보** (클래스당 5)

- biped: 고릴라, 이족보행 로봇, 캥거루, 펭귄, 곰(직립)
- quadruped: 개, 말, 사슴, 코끼리, 고양이
- bird: 갈매기, 독수리, 오리, 학, 앵무새
- insect: 개미, 사마귀, 딱정벌레, 잠자리, 메뚜기

총 생성 수: 4클래스 × 5객체 × 2조건 × 3시드 = **120런**.
객체당 ~233초 기준 1 GPU 약 7.8시간 → **4090 4장 병렬 시 약 2시간**.
(모델 로드 분산 고려. 프리뷰 렌더는 이 실험에서 채점에 쓰므로 게이팅하지 않는다.)

**선택 arm (여력 시)**: biped 한정 A포즈 vs T포즈 문구 비교 (+30런).
문서화된 humanoid 자세 요구가 툴마다 상충(Mixamo=T, AccuRig=A)하므로,
biped A포즈 유지 여부(⭐ 항목 ①)를 데이터로 결정할 수 있다.

## 3. 리거 (측정 도구)

| 도구 | 역할 | 비고 |
| --- | --- | --- |
| UniRig (오픈소스) | **주 측정** — 로컬 대량 실행, 실패 해부 가능 | taxonomy-free. 4090에서 구동 확인 필요(선행 작업 P1) |
| Tripo rig API + rig-check | **부 측정** — 상용 기준선, 클래스 템플릿 기반 | rig-check가 공짜 이진 지표. API 비용·쿼터 사전 확인 |

두 리거는 부류가 다르므로(taxonomy-free vs 템플릿) 결과가 갈리면 그 자체가 발견이다.

## 4. 측정 (종속변수) — 4단계 깔때기

| 단계 | 지표 | 방법 |
| --- | --- | --- |
| S1. T2I 자세 준수 | 이미지가 자세 문구를 충족하는가 (O/X) | 사람 채점. VLM 사전 분류 + 사람 검수로 부담 절감 |
| S2. I2O 자세 유지 | 메시가 자세를 유지하는가 (O/X) + 얇은 구조 소실 여부 (곤충 다리·날개 등) | 4뷰 렌더 채점. **S1=O인 것만** 대상 |
| S3. 리깅 성공 | (a) rig-check 통과 (b) 리깅 완료 (c) 스켈레톤 타당성 (본 수·대칭·관절 위치, 3점 척도) | (a)(b) 자동, (c) 사람 채점 |
| S4. 애니메이션 (선택) | 걷기 사이클 리타게팅 후 메시 왜곡 (3점 척도) | Tripo 리타게팅 또는 Blender. 여력 시 |

**실패 태깅 taxonomy** (S2·S3 실패 건 전수):
`pose_folded`(사지 접힘/붙음) / `limbs_fused`(사지 상호 융합) / `thin_structure_lost`(얇은 구조 소실)
/ `asymmetry`(비대칭) / `topology`(비다양체 등 메시 결함) / `rigger_error`(리거 자체 오류) / `other`

이 태깅이 H3의 데이터이자, 논문화 시 "실패 원인 분포" 그림이 된다.

## 5. 분석 계획

1. 주 결과표: 클래스 × 조건별 S3 성공률 (n=15/셀). 비율 검정은 Fisher exact.
2. 깔때기 분석: S1→S2→S3 통과율을 조건·클래스별로 — **어느 단계가 병목인가** (H2).
3. 실패 원인 분포: 태그별 비율, 스캐폴딩 on/off 간 분포 차이 (H3).
4. 리거 간 비교: UniRig vs Tripo 성공 패턴 차이 → 리깅 툴 선정 근거.
5. (선택 arm) biped A vs T 성공률 → ⭐ 항목 ① 결정.

## 6. 실행 절차

- **P0 파일럿 (0.5일)**: bird 1클래스 × 2객체 × 2조건 × 2시드 = 8런으로 전 절차 리허설.
  채점 기준 조율, UniRig 입출력 확인. 문제 없으면 본실험.
- **P1 선행 작업**: ① UniRig 설치·구동 확인 (입력 면수 제한 확인 — 필요시 데시메이션 단계 추가,
  단 조건 간 동일 적용) ② Tripo API 키·비용 확인 ③ off 조건용 프롬프트 빌더 분기
  (`t2i_prompt_builder.py`에 자세 문구 skip 플래그 — 실험용, 프로덕션 경로 불변)
  ④ rig_type은 수동 주입 (의도분석 산출물 미도착과 무관하게 `build_t2i_prompt` 직접 호출로 가능,
  스냅샷 §4-1에서 5개 값 라우팅 검증됨)
- **P2 본실험 (1일)**: 120런 생성 + 리깅. 결과는 런별 1행 CSV
  (object, class, scaffold, seed, s1, s2, s3a, s3b, s3c, tags, 시간, 경로).
- **P3 채점·분석 (1~2일)**: 사람 채점(가능하면 2인 이중 채점, 불일치만 합의), 분석, 실패 갤러리 작성.

## 7. 판정과 후속

| 결과 시나리오 | 후속 조치 |
| --- | --- |
| on ≫ off 단조, 병목 없음 | 문구 유지 확정. 내부 자료화. CONTEXT.md §4 "검증 완료"로 갱신 |
| 특정 단계 병목 (예: S1 준수율 낮음) | 병목 단계 개선 (프롬프트 강화 / I2O 파라미터) + 논문화 검토 |
| 클래스별 역전·자세 무관 실패 지배 | H3 확정 → 스캐폴딩 재설계 + **논문화 우선 검토** |
| off도 충분히 성공 | 스캐폴딩 무용 → 문구 제거, 파이프라인 단순화 |

어느 시나리오든 **리깅 툴 선정(⭐)의 1차 데이터**가 되고, ①②③④ 항목이 함께 풀린다.

## 8. 리스크

- UniRig가 95만 면 입력을 못 받을 수 있음 → 데시메이션 전처리 (조건 간 동일 적용이면 실험 유효)
- Tripo API 비용/쿼터 → 부 측정이므로 최악의 경우 UniRig 단독으로 진행
- 사람 채점 부담 (S1·S2 240건, S3c ~120건) → VLM 사전 분류로 절감, 단 최종 판정은 사람
- 시드 3이 부족할 수 있음 → 파일럿에서 시드 간 분산 확인 후 증감
